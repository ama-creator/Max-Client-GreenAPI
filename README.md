# MAX × GREEN-API

Минимальный веб-клиент для обмена текстовыми сообщениями в MAX. React 19, TypeScript в строгом режиме, Vite, Zod. Адаптивный интерфейс по мотивам MAX Web: список чатов, личная переписка, создание диалога по номеру телефона.

## Запуск

Нужен Node.js 22.12+ (или 24+).

```bash
npm ci
npm run dev
```

Откройте http://127.0.0.1:5173. Для знакомства без ключей нажмите **«Открыть демоверсию»**. В деморежиме используются вымышленные сообщения, запросы в GREEN-API не выполняются.

```bash
npm run build     # TypeScript + production-сборка в dist/
npm run preview   # локальная проверка production-сборки
npm test          # модульные тесты API, хранилища и получения уведомлений
npx playwright install chromium
npm run test:e2e  # сценарии в браузере, десктоп и мобильный экран
```

Если установлен Google Chrome, браузер можно не скачивать: `PLAYWRIGHT_CHANNEL=chrome npm run test:e2e`.

## Подключение к MAX

1. Создайте инстанс **MAX** в [личном кабинете GREEN-API](https://console.green-api.com/). Инстанс WhatsApp для этой реализации не подходит.
2. Авторизуйте инстанс: отсканируйте QR-код из личного кабинета приложением MAX.
3. Настройте получение через HTTP API: `webhookUrl` должен быть пустым, `incomingWebhook` — `yes`. Для статусов доставки включите `outgoingWebhook`, для копий исходящих из API — `outgoingAPIMessageWebhook`. Изменения могут применяться несколько минут. Приложение проверяет необходимые настройки при подключении и **не перезаписывает** конфигурацию инстанса.
4. Введите **idInstance**, **apiTokenInstance** и **apiUrl**, скопированные из своего инстанса. Адрес API отличается между кластерами, поэтому он вводится явно, без предположений по номеру инстанса.
5. Нажмите **«Новый чат»**, введите телефон в международном формате и при желании имя. Приложение получает внутренний `chatId` методом `CheckAccount` и использует его для дальнейшей переписки.
6. Отправьте текст. Попросите получателя ответить в приложении MAX. Ответ появится в этом же чате.

Учитывайте ограничения своего тарифа и настройки приватности получателя. Для приёма сообщений эта вкладка должна оставаться открытой. Не запускайте другого потребителя очереди на том же инстансе: `DeleteNotification` удаляет уведомление для всех потребителей. Между вкладками этого приложения получение координируется через Web Locks API, если браузер его поддерживает.

## Реализация

```text
src/
  components/   форма подключения, доступный modal на native dialog
  lib/
    api.ts            типизированный HTTP-клиент, схемы ответов, безопасные ошибки
    chat-store.ts     состояние чатов и сообщений, обработка событий, дедупликация
    polling.ts        последовательное получение, ACK и backoff
    demo.ts           явно обозначенный демонстрационный режим
  App.tsx       интерфейс чатов и отправка сообщений
  styles.css    адаптивные стили
e2e/            интеграционные браузерные сценарии с подменой GREEN-API
```

- Вход проверяет `GetStateInstance` и `GetSettings`; создание чата использует `CheckAccount`. Отправка — **SendMessage**, получение — **ReceiveNotification → DeleteNotification**.
- Один последовательный long-poll с `receiveTimeout=25`; следующий запрос начинается после обработки и ACK. Для временных ошибок — экспоненциальная задержка до 30 секунд; для 401/403/404 — остановка с сообщением пользователю. При выходе и размонтировании все запросы отменяются.
- Сообщение сохраняется в `sessionStorage` **перед ACK**. При сбое подтверждения повторное событие обрабатывается без дубликатов по `idMessage`. Если хранилище недоступно, уведомление остаётся в очереди. Неподдерживаемые события подтверждаются, текстовые сообщения с повреждённой структурой не удаляются молча.
- Входящий текст и текст с URL попадают в тот же диалог по внутреннему MAX `chatId`. Поддерживаются статусы `sent`, `delivered`, `read`, `failed`, включая приход статуса раньше HTTP-ответа на отправку. `sent` означает принятие GREEN-API, а не доставку получателю.
- Нет автоматических повторов **SendMessage**: при сетевом обрыве сервер мог принять запрос. Такое сообщение получает статус «неизвестен» и рекомендацию проверить MAX. Явно отклонённое сообщение можно отправить повторно вручную. Прерванная перезагрузкой отправка также восстанавливается с неизвестным статусом.
- Enter отправляет сообщение, Shift+Enter добавляет строку. Учитывается IME composition. Лимит текста — 4000 символов. Кнопки и поля подписаны, есть управление с клавиатуры, focus trap в диалогах, адаптация к мобильным экранам и reduced motion.

## Данные и границы решения

Токен находится **только в оперативной памяти**; он не попадает в URL приложения, хранилище браузера, логи или репозиторий. Перезагрузка требует повторного ввода данных. Запросы идут непосредственно из браузера на HTTPS-хост GREEN-API; поле `apiUrl` ограничено доменами API сервиса. Согласно протоколу GREEN-API токен присутствует в пути запроса и виден владельцу браузера в Network.

Чаты и тексты сохраняются только в `sessionStorage`, раздельно для каждого инстанса. Выход удаляет данные текущего аккаунта из вкладки. Это локальное состояние клиента, не серверная история и не долговременное хранилище: очистка данных браузера или закрытие вкладки может удалить переписку. Для промышленного многопользовательского продукта потребовались бы серверный посредник, серверные сессии и зашифрованное хранение секретов; в задании реализован автономный фронтенд с вводом собственных данных пользователя.

Вне объёма задания: медиа, группы, звонки, синхронизация старой истории, поиск по сообщениям, серверное хранение. Демоверсия намеренно не имитирует реальную доставку.

## Проверка

Модульные тесты проверяют нормализацию номера, безопасный адрес API, запросы и ошибки, привязку входящего сообщения к диалогу, повторную доставку уведомления, порядок статусов, сохранение и восстановление сессии, ACK после записи и поведение при сбое хранилища. Браузерные сценарии проходят путь от ввода ключей до отображения ответа и ACK на мобильном и настольном экранах. GREEN-API в тестах подменён: для проверки реальной доставки требуется авторизованный инстанс и второй аккаунт MAX.
